## Context

现有内容审核在一个模型请求中同时返回安全 findings、decision、risk score 和单一 quality score，随后仅进行数值截断并在缺失时回退到 60。该分数写入 `review_jobs` 和 `works`，并直接用于 feed 的质量排序、热门内容准入及创作者统计。现有工作流已经能记录顺序步骤和模型版本，因此本变更可在当前架构内增加独立评估节点，无需引入图编排框架。

## Goals / Non-Goals

**Goals:**

- 让 0–100 总分来自稳定、透明、程序化的计算，而非模型直接估分。
- 让每个分项有原文依据和可操作反馈，并能追踪 rubric、模型与内容版本。
- 让质量评估故障与安全审核隔离，不通过虚假默认分掩盖失败。
- 建立可自动回归的离线评测基线，为模型或 prompt 变更提供发布依据。

**Non-Goals:**

- 本期不进行联网事实核查、查重或版权归属判定。
- 本期不自动学习或动态调整 feed 中的质量权重和 60 分准入线。
- 本期不回填所有历史作品；仅提供以后可复用的重评能力。
- 本期不引入 LangChain、LangGraph、多模型投票或人工标注平台。

## Decisions

### 1. 安全审核与质量评估为两个独立节点

标准化输入之后分别运行安全审核和质量评估，再由聚合步骤保存结果。首版可顺序执行以最小化改动，但接口边界 SHALL 允许以后并行。质量节点失败不会篡改安全 decision；安全节点失败仍按现有审核失败策略处理。

替代方案是继续一次调用同时完成两项任务。该方案成本较低，但难以单独迭代 rubric、校准分数或隔离失败，因此不采用。

### 2. 五维 0–4 等级加固定权重

采用以下 rubric v1：

| 维度 | 权重 | 主要判断 |
|---|---:|---|
| factual_credibility | 25 | 事实陈述的可支持性、来源表达、限定条件和内部一致性 |
| completeness | 20 | 是否回应主题、信息是否充分、关键背景与结论是否完整 |
| logic_structure | 20 | 组织结构、论证连贯性、段落关系和标题正文一致性 |
| information_value | 20 | 具体性、洞察、实用性及相对空泛重复内容的增量价值 |
| readability | 15 | 清晰度、语言流畅性、冗余、格式和目标读者适配度 |

各维度等级只能为整数 0–4。总分计算为：

`round(sum(level / 4 * weight), 2)`

首版不使用 N/A，从而保持跨内容类型的分母一致。创意或主观内容的 factual_credibility 不评价外部真伪，而评价是否把主观表达伪装成事实、是否虚构依据及内部是否自洽。

替代方案是让模型直接给每维 0–100 分。更细的刻度会制造虚假精度并增加重复运行波动，因此不采用。

### 3. 模型输出证据，程序负责验证和计算

质量模型只返回 rubric version 和五个维度的 `level`、`evidence[]`、`reason`、`suggestion`。证据分为：

- `quote`：包含 `excerpt`，必须可在标准化标题或正文中定位。
- `holistic`：用于结构等整体判断，不要求虚构短引文，但必须描述可检查的文章位置或关系。

使用运行时 Schema 校验精确维度集合、整数范围、必填字段及证据联合类型；随后执行语义校验和确定性计算。建议引入 Zod，因为项目当前仅有 TypeScript 类型，无法校验模型运行时输出；若不希望增加依赖，可实现等价的专用 validator，但不能降低同一校验契约。

首次失败时将明确的校验错误反馈给模型进行一次 repair。repair 仍失败则记录 `failed`，不使用当前 `clamp(..., 60)` 式回退。

### 4. 在审核记录中保存快照，在作品上保留兼容投影

在 `review_jobs` 增加可为空的 `quality_status`、`quality_details JSONB` 和 `quality_rubric_version`。`quality_details` 保存维度快照、计算输入和校验元数据；已有 `quality_score` 保存本次成功总分。`works.quality_score` 继续保存当前内容版本最近一次成功评估的总分，避免立即修改 feed 和 dashboard 的公共字段。

质量评估失败时，本次审核记录写入失败状态和错误摘要，作品分数不得被设为默认值。新内容版本提交时，其旧分数不能继续代表新版本；发布新版本前后应根据对应审核结果更新或清空当前投影。

替代方案是立即创建完全规范化的维度明细表。五个维度固定且结果以整体版本化快照读取，JSONB 更利于 rubric 演进；待产生维度级查询或分析需求后再规范化。

### 5. 保留发布兼容，收紧推荐语义

安全审核通过且质量评估失败时允许发布，因为质量系统可用性不应变成隐式内容安全结论。未评分内容不进入当前依赖 `quality_score >= 60` 的热门推荐，也排在质量排序之外；普通最新、点赞排序和作品详情仍可访问。创作者统计平均值只统计成功评分，并在没有成功评分时表达为未评分，而不是数值 0。

### 6. 以固定数据集评价评分器，而非评价单条输出观感

建立至少 100 条首版金标样本，覆盖长短内容、教程、观点、叙事、营销倾向、标题党和边界质量案例。每条由至少两名标注者依据同一 rubric 独立评分；分歧超过一个等级的维度进入仲裁。数据中保存内容、分项等级、总分、内容类型和数据集版本，不包含真实用户敏感数据。

评测命令固定 temperature、模型参数和 prompt/rubric 版本，输出机器可读 JSON 报告。首版门槛采用规格中的四项指标；门槛用于阻止未经验证的评分器升级，不承诺模型结果绝对客观。

## Risks / Trade-offs

- [单模型仍存在主观性和漂移] → 通过分项锚点、固定参数、版本记录、金标回归和重复运行指标控制。
- [模型无法完成真实事实核查] → 将 factual_credibility 限定为正文可观察的可信表达；后续事实核查作为独立能力。
- [独立调用增加延迟和成本] → 首版记录调用耗时与 token；安全和质量接口保持可并行，后续按监控数据优化。
- [质量评估失败后仍发布会降低推荐覆盖] → 明确未评分状态并支持重评，不用不可信的默认分换取覆盖率。
- [rubric 升级使跨版本分数不可直接比较] → 保存 rubric 版本，升级前运行同集对照；必要时批量重评活跃内容。
- [JSONB 不利于维度级 SQL 分析] → 首版优先版本化快照；确有分析需求时增加派生表或物化视图。

## Migration Plan

1. 以可空字段扩展审核记录，不改变已有 `quality_score` 类型及 API 字段。
2. 实现 rubric v1、运行时校验、计算器和独立质量节点，并先通过单元测试与离线金标评测。
3. 在非生产环境比较旧直接分数与新 rubric 分数，确认分布和现有 60 分推荐阈值的影响。
4. 启用新评分写入；历史记录保留旧分数但无 rubric version，视为 legacy，不混入新评测统计。
5. 观察失败率、延迟、分数分布与推荐覆盖，再决定是否重评历史活跃内容或调整分发阈值。

回滚时停止独立质量节点和新字段写入，恢复旧审核调用中的质量分逻辑；新增可空字段与历史快照保留，不需要破坏性迁移。
